## 一、主线：这四天做了什么、为什么、重点

### 核心命题

项目长期目标是对 VLA 做量化（PTQ），但前提是**先有一个可靠的、可复现的仿真 baseline**。因此这四天的主线只有一句话：

> **找到并固化一个 LIBERO 量化 baseline，同时查清「为什么所有公开 checkpoint 都复现不出论文 87.3%」。**

围绕这个命题，四条子线并行推进，最终形成一个清晰结论。

---

### 线 1：逐个评测公开 checkpoint，收敛量化 baseline 选型

**做了什么**：系统性评测了 5 个公开 SmolVLA/LIBERO checkpoint 的四 suite 成绩。

**为什么**：量化必须有一个 FP/BF16 参照点。选哪个 checkpoint 做 baseline，直接决定量化研究的说服力。

**时间推进与重点**：

| 日期 | 动作 | 关键产出 |
|---|---|---|
| 8-22 | 汇总 A 类 `lerobot/smolvla_libero`（69.2%），跑完 C 类 `tiantianx`（59.5%） | 两个公开 cp 都远离论文，且 recipe 更贴论文的 C 类反而更低 |
| 8-23 | HF Hub 全量搜索 `smolvla`+`libero`，发现 2 个高价值新候选 | 搭建 `preflight_policy.py` 自动推导 rename_map 的流水线 |
| 8-24 | 跑完 D 类 `k1000dai`（65.5%）；hfvla_ckpts100k smoke 失败→审计关闭；核实官方 hfvla 架构已漂移（32层/0.5） | 明确 A/D/C 三类的 recipe 差异 |
| 8-25 | 跑完官方 hfvla（61.2%），五模型全测完 | **baseline 定论：A 类 69.2%** |

**最终结论（重点）**：没有任何公开 checkpoint 接近论文 87.3%（最佳 69.2%，差 18pp），因此**量化退化只能相对自测 baseline（A 类 69.2%）报告，不能对照论文数字**。

---

### 线 2：审计「为什么复现不出论文」——发现 MuJoCo 版本是决定性变量

**做了什么**：启动 Table-2 严格复现排查（AUDIT_RECORD 的 Phase 0–16），逐阶段审计环境、契约、协议、checkpoint。

**为什么**：与其盲目调参，不如系统排查「论文 87.3% 的 gap 到底来自哪里」——是环境、协议、还是 checkpoint 本身。

**重点进展**（8-25 的关键突破）：

- **Phase 6 决定性发现**：MuJoCo 版本从 3.8.1 降到 3.3.2，A 类 Spatial Task5 从 **0/10 飙到 8/10（+80pp）**。
- 这意味着：之前五模型 benchmark（全在 3.8.1 下）的数字**可能被系统性低估**，论文 87.3% 的 gap 中有一部分是 MuJoCo 版本贡献。
- 紧接着启动「3.3.2 下重测 A 类四 suite」（Phase 6 后续），验证版本结论是否全面成立。

**其他已闭环的审计**（8-25 完成）：环境冻结、Integration Smoke、Observation Contract（8D state）、Action/Gripper Contract（无 flip hack）、Eval Protocol（n_action_steps=1）、Checkpoint Provenance、Batch 语义源码审计。

---

### 线 3：引入 Meta-World 作为第二 benchmark

**做了什么**：在 LIBERO 之外，接入 `lerobot/smolvla_metaworld` 跑 MT50 全量评估。

**为什么**：单一 benchmark（LIBERO）不足以支撑量化研究的稳健性，需要第二基准交叉验证「量化退化是否普遍」。

**重点**：8-24 重建环境 + 单任务冒烟（push-v3 100%），8-25 MT50 全量出结果（四难度算术平均 54.1% vs 论文 57.3%）。

---

### 线 4：论文 recipe 自微调（拿受控 baseline 的唯一路径）

**做了什么**：既然公开 checkpoint 都不行，尝试自己按论文 recipe 训练。

**为什么**：这是「拿到与论文同源的受控 baseline」的唯一途径——公开 checkpoint 要么架构漂移、要么 recipe 不对。

**重点**：8-24 从 `smolvla_base` 微调踩坑；8-25 决策改走 `--policy.type=smolvla`（从零初始化 expert 的 strict 路线），启动 fresh-expert 100k 训练。（该训练 8-26 已停止，训练线暂缓。）

## 二、遇到的问题与解决方案

### 环境 / 依赖类

| 问题 | 解决方案 |
|---|---|
| conda activate 覆盖环境变量（MUJOCO_GL 警告） | 属预期；用 `/proc/<PID>/environ` 验证实际进程环境，不要信当前 shell 的 printenv |
| `ImportError: 'accelerate' is required` | `pip install -e ".[training]"`（accelerate 1.14.0） |
| torchcodec 加载失败（缺 ffmpeg libavutil.so） | 仅 WARNING，自动 fallback `pyav`，可忽略 |
| `num2words` 缺失（SmolVLM processor 需要） | `pip install num2words==0.5.14` |
| `huggingface-cli` 已废弃 | 改用 `hf download` |
| pip 走代理极慢 | `env -u http_proxy ... pip install --proxy ""` + 国内源（详见 8-20 记录） |

### 评测参数 / 接口类

| 问题 | 解决方案 |
|---|---|
| `Cannot specify both --policy.path and --policy.type` | 二选一；`--policy.path` 已隐含类型 |
| lerobot-train 报 `'repo_id' argument missing` | 加 `--policy.repo_id=...`（本地不推 hub 也强制要求） |
| Meta-World env 单相机 vs policy 要 camera1/2/3 | `--rename_map='{"observation.image":"observation.images.camera1"}'` + `--policy.empty_cameras=2` |
| Meta-World config `state=[6]` 与 normalizer 实际 4D 不一致 | **实测无需改 config**（lerobot state 通道有 pad 兜底），保持官方文件原样 |
| 不同 checkpoint 相机 key 命名不同（camera1/2 vs image/wrist_image vs image/image2） | 用 `preflight_policy.py` 从 config 自动推导 rename_map，无需手写 |
| 后台进程 EGL 配置判断 | 用 `/proc/<PID>/environ`，不要用当前 shell |

### 关键决策 / 路线类

| 问题 | 结论 |
|---|---|
| hfvla_ckpts100k smoke 0/1 失败 | 审计发现是 **2.2B-Instruct 底座 + pi 无 state 数据训练**，非论文结构 → 判定不可修，关闭 |
| 官方 HuggingFaceVLA/smolvla_libero 架构漂移（32层/0.5/Instruct） | 仅作 simulator 正确性 reference，不作论文结构量化 baseline |
| 自微调用 `smolvla_base`（含 robotics pretraining）不符合 strict Table-2 | 改走 `--policy.type=smolvla --load_vlm_weights=true`（仅 pretrained VLM + 随机 expert） |
| MuJoCo 3.8.1 下 Task5=0/10 异常 | 定位为 MuJoCo 版本问题（3.3.2 下 8/10），非 checkpoint 缺陷 |
| 数据集缺失 push-back-v3（total=49 vs 配置 50） | 该任务描述与 push-v3 相同，模型训练时见过；全量评估含 50 任务，报告注明即可 |

## 三、数据与结果

### 3.1 LIBERO 五公开 checkpoint 四 suite 成绩（统一协议：seed=1000, n_action_steps=1, num_steps=10）

| Suite | 论文 | lerobot (A) | k1000dai (D) | HuggingFaceVLA (B) | tiantianx (C) |
|---|---:|---:|---:|---:|---:|
| Spatial | 90% | **81%** | 64% | 65% | 76% |
| Object | 96% | 60% | **82%** | 71% | 59% |
| Goal | 92% | **77%** | 70% | 72% | 63% |
| Long | 71% | **59%** | 46% | 37% | 40% |
| **平均** | **87.3%** | **69.2%** | 65.5% | 61.2% | 59.5% |

**要点**：
- 最佳 A 类 69.2%，距论文 **-18.1pp**；无一接近 87.3%
- 各 suite 最佳分属不同模型（Object 属 D，其余属 A）→ 系统性训练差距，非单任务偏科
- recipe 最贴论文的 C 类反而最低（59.5%）；D 类 recipe 最贴（batch64）但成绩仅 65.5% → **recipe 吻合 ≠ 成绩吻合**
