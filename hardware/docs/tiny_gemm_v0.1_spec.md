# tiny_gemm v0.1 规格草案

`hardware/` 目录下第一版矩阵引擎的设计约定。**接口与数值行为是验收依据；状态名称仅为建议实现。**

本版目标：用一个有符号整数乘加单元完成固定尺寸矩阵乘法，支持存储访问等待与完成响应反压，并自动验证全部结果。

---

## 1. 功能与范围

$$C_{m,n}=\sum_{k=0}^{7}A_{m,k}W_{k,n}$$

| 项目 | v0.1 规定 |
|---|---|
| RTL 模块名 | `tiny_gemm` |
| A 尺寸 | 4×8 |
| W 尺寸 | 8×4 |
| C 尺寸 | 4×4 |
| A、W 数据类型 | 8 位有符号二进制补码 |
| 乘积 | 16 位有符号整数 |
| 累加和 C | 32 位有符号整数 |
| 计算资源 | 一个乘法器、一个累加器，重复使用 |
| 执行顺序 | `m → n → k`，其中 k 最内层 |
| 并发任务数 | 1 |
| 存储布局 | 行优先 |
| 时钟 | 单时钟域，上升沿工作 |
| 复位 | 同步低有效复位 |
| 完成条件 | 16 个 C 元素全部完成写握手 |

**本版不包含**：bias、scale、FP8、稀疏跳零、DMA、AXI、多个 PE、运行时可变尺寸。

---

## 2. DUT 与 testbench 的边界

**DUT 内部**：

- 命令与完成响应控制
- `m / n / k` 循环计数器
- A/W 读地址生成
- 输入数据寄存器
- 乘法器与累加器
- C 写地址和数据生成

**Testbench 提供**：

- 时钟与复位
- 启动命令
- A、W 的只读存储模型
- C 的可写存储模型
- 软件式矩阵乘法参考计算
- 协议检查、结果检查与超时保护

**A/W/C 存储器放在 DUT 外部。** 这样将来可以把 TB 存储模型换成片上 RAM 封装，而不必改矩阵计算逻辑。

---

## 3. 命令与完成接口

所有接口都在上升沿以 `valid && ready` 判定一次传输。

| 信号 | 相对 DUT 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `clk` | 输入 | 1 | 时钟 |
| `rst_n` | 输入 | 1 | 同步低有效复位 |
| `cmd_valid` | 输入 | 1 | 启动命令有效 |
| `cmd_ready` | 输出 | 1 | 可以接收启动命令 |
| `done_valid` | 输出 | 1 | 当前矩阵任务已完成 |
| `done_ready` | 输入 | 1 | 外部接收完成通知 |
| `busy` | 输出 | 1 | 已接收任务，尚未交付完成通知 |

尺寸、地址起点、格式固定，**第一版命令只有启动握手，没有参数字段**。

规则：

1. `IDLE` 状态可以接收命令。
2. 命令握手后开始执行，`busy=1`、`cmd_ready=0`。
3. 最后一个 C 元素写握手完成后，才允许产生 `done_valid`。
4. 当 `done_valid=1 && done_ready=0` 时，保持 `done_valid=1`。
5. 完成通知被接收后，返回 `IDLE`。
6. **完成通知被接收的同一拍，不接收下一条命令。** 下一周期才重新拉高 `cmd_ready`。

> 若外部持续保持 `cmd_valid=1`，每次 `cmd_ready=1` 的上升沿都会形成新命令。因此命令驱动器应在握手后撤销 `cmd_valid`。

## 4. A/W 读取接口

A 和 W 使用两套相同结构、相互独立的接口。

| 信号 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `a_req_valid` | 输出 | 1 | A 读请求有效 |
| `a_req_ready` | 输入 | 1 | A 存储模型接受读请求 |
| `a_req_addr` | 输出 | 5 | A 元素地址，0～31 |
| `a_rsp_valid` | 输入 | 1 | A 返回数据有效 |
| `a_rsp_ready` | 输出 | 1 | DUT 接收 A 数据 |
| `a_rsp_data` | 输入 | 8 | A 的补码数据 |
| `w_req_valid` | 输出 | 1 | W 读请求有效 |
| `w_req_ready` | 输入 | 1 | W 存储模型接受读请求 |
| `w_req_addr` | 输出 | 5 | W 元素地址，0～31 |
| `w_rsp_valid` | 输入 | 1 | W 返回数据有效 |
| `w_rsp_ready` | 输出 | 1 | DUT 接收 W 数据 |
| `w_rsp_data` | 输入 | 8 | W 的补码数据 |

读取规则：

- 请求和返回是两次独立握手。
- 请求等待时，DUT 必须保持 `req_valid` 和地址不变。
- 每个接受的请求必须产生且只产生一次返回，复位取消除外。
- 返回等待时，存储模型必须保持 `rsp_valid` 和数据不变。
- 每个端口最多允许一个未完成请求。
- **数据最早在请求握手的下一周期返回，不支持同拍返回。**
- A 和 W 的请求接受时间、返回时间可以不同。

第一版**串行**读取以简化控制：

```text
发 A 请求 → 收 A 数据 → 发 W 请求 → 收 W 数据 → 做一次乘加
```

这会牺牲一些吞吐，但状态机容易理解。后续可改成并行发出 A/W 请求，外部接口保持兼容。

## 5. C 写入接口

| 信号 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `c_wr_valid` | 输出 | 1 | C 写入有效 |
| `c_wr_ready` | 输入 | 1 | 存储模型接受写入 |
| `c_wr_addr` | 输出 | 4 | C 元素地址，0～15 |
| `c_wr_data` | 输出 | 32 | 32 位补码结果 |

规则：

- `c_wr_valid && c_wr_ready` 的上升沿表示该元素写入完成。
- 等待期间，`c_wr_valid`、地址和数据必须保持不变。
- 本版没有额外的写响应通道。
- **C 存储模型必须在写握手时更新对应存储位置。**
- 写入顺序必须为地址 `0、1、…、15`，每个地址恰好写一次。

> 「握手即写入完成」的约定适用于本地存储接口。以后接总线时，应由适配模块处理总线自己的写完成语义。

## 6. 地址与数值规则

所有地址均为**元素索引，不是字节地址**：

$$
\begin{aligned}
a\_addr &= 8m+k\\
w\_addr &= 4k+n\\
c\_addr &= 4m+n
\end{aligned}
$$

例如计算 `C[1,2]`：

| k | A 地址 | W 地址 |
|---:|---:|---:|
| 0 | 8 | 2 |
| 1 | 9 | 6 |
| 2 | 10 | 10 |
| … | … | … |
| 7 | 15 | 30 |

结果写入 C 地址 `4×1+2 = 6`。

数值计算严格规定为：

1. A/W 按有符号 INT8 解读。
2. 计算完整的 16 位有符号乘积。
3. 将乘积符号扩展到 32 位。
4. 与 32 位累加器相加。
5. 每个新 C 元素从零开始累加。

$$acc_{k+1}=acc_k+\operatorname{signextend}_{32}(A_{m,k}W_{k,n})$$

本版不存在舍入或截断。保守界限：

$$|C_{m,n}|\leq 8\times128\times128=131072$$

所以 INT32 足以容纳结果。

> **RTL 中必须显式处理 signed 和符号扩展。** 例如 `8'hFF` 表示 −1，不能被当成 255。

## 7. 状态机

| 状态 | 主要动作 | 离开条件 |
|---|---|---|
| `IDLE` | 等待命令 | 命令握手 |
| `INIT_C` | `acc=0`、`k=0` | 下一周期 |
| `A_REQ` | 提交当前 A 地址 | A 请求握手 |
| `A_WAIT` | 接收并保存 A | A 返回握手 |
| `W_REQ` | 提交当前 W 地址 | W 请求握手 |
| `W_WAIT` | 接收并保存 W | W 返回握手 |
| `MAC` | 执行一次累加 | 非最后一项则继续读取，否则进入写回 |
| `C_WRITE` | 提交当前 C 结果 | C 写握手 |
| `DONE` | 保持完成通知 | 完成响应握手 |

循环更新规则：

- 命令握手时设置 `m=0、n=0`。
- `MAC` 状态中：
  - `k<7`：累加后 `k=k+1`，转 `A_REQ`。
  - `k=7`：累加后转 `C_WRITE`。
- `C_WRITE` 握手后：
  - `n<3`：`n=n+1`，转 `INIT_C`。
  - `n=3 && m<3`：`m=m+1、n=0`，转 `INIT_C`。
  - `m=3 && n=3`：转 `DONE`。

> **最后一次累加完成后，下一周期再输出累加器作为写数据。** 避免非阻塞赋值导致写出的结果少加最后一项。

`rtl/tiny_gemm.sv` 额外使用一个 `S_RESET` 编码（`4'd15`）表示「复位采样期间」的状态，用于让 `busy` 在复位时明确为 0；其余状态与上表一一对应。

---

## 8. 复位行为

在任意上升沿采样到 `rst_n=0` 时：

- 取消当前任务，返回 `IDLE`。
- 清除内部计数器、操作数寄存器和累加器。
- 清除待发送请求、写入和完成通知。
- 取消的任务不再产生 `done_valid`。

复位期间对外：

| 信号 | 规定 |
|---|---|
| `cmd_ready` | 0 |
| `busy` | 0 |
| A/W 请求 `valid` | 0 |
| A/W 返回 `ready` | 0 |
| C 写 `valid` | 0 |
| `done_valid` | 0 |

TB 的存储模型必须同步复位，并丢弃尚未返回的请求。A/W/C 的存储内容可以保留。

被复位中断的任务可能已经写入部分 C；这些内容视为无效。下一条完整任务会重写全部 16 个结果。

> 该复位规则依赖 DUT 和存储模型共同取消未完成事务。以后接入真实总线时需要重新定义取消或排空机制。

## 9. Testbench 验收要求

| 测试 | 输入或条件 | 检查重点 |
|---|---|---|
| 全零 | A/W 全零 | C 全零 |
| 全一 | A/W 全为 1 | 每个 C 都为 8 |
| 正负混合 | 包含正数、负数和零 | 有符号计算正确 |
| 极值 | 包含 −128、127 | 乘积位宽与符号扩展正确 |
| 地址定向 | 少量指定位置非零 | 行列索引、布局正确 |
| 随机矩阵 | 固定并记录 seed | 全部输出匹配参考模型 |
| 存储等待 | 请求接受和数据返回加入延迟 | 不丢请求、不重复累加 |
| 写入反压 | 延迟 `c_wr_ready` | 写地址与数据保持稳定 |
| 完成反压 | 延迟 `done_ready` | 完成通知保持，不接收新任务 |
| 连续任务 | 连续执行不同输入 | 累加器与循环状态正确清空 |
| 中途复位 | 在读等待、计算或写等待时复位 | 旧任务取消，新任务恢复 |

对于一个**未被复位中断**的任务，必须检查：

| 事件 | 精确数量 |
|---|---:|
| 命令握手 | 1 |
| A 读请求 / 返回握手 | 各 128 |
| W 读请求 / 返回握手 | 各 128 |
| C 写握手 | 16 |
| 完成握手 | 1 |

参考结果用 TB 中独立的三重循环计算，**不读取 DUT 内部 `acc` 作为答案**。检查 C 时使用能捕获 X/Z 的比较方式，例如 `!==`。

还应检查：

- 没有命令不能写 C 或产生完成响应。
- 所有等待中的发送端字段保持稳定。
- 每次写入的地址顺序与数据正确。
- 最后一个 C 写入前不能报告完成。
- **故意修改一个预期结果时，测试必须失败。**

## 10. 性能记录与第一版通过标准

第一版先记录，不设目标 MHz：

- 命令握手到最后一次 C 写握手的周期数
- 等待 A/W 请求或返回的周期数
- 等待 C 写入的周期数
- 等待完成通知被接收的周期数，**单独记录**

> **执行延迟不要包含外部拖延接收完成通知的时间。** 否则调整 `done_ready` 会让计算性能看起来发生变化。

为避免死锁，测试环境限制每次随机等待不超过 8 周期，并设置单任务 10,000 周期超时。这是本版测试条件，不是引擎对任意外部停顿都能按时完成的承诺。

第一版完成标准：

> **固定尺寸计算正确；所有握手遵守协议；等待和复位场景通过；回归能够识别故意注入的错误；可独立运行并生成日志。**
